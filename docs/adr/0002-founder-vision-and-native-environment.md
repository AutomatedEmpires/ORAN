# 0002. Founder vision and native environment amendment

- Status: Accepted for founder direction; full blueprint approval D0 remains open
- Date: 2026-11-02
- Deciders: Founder, by explicit continuation request
- Related: D2, D8, D9, D17, D18; C8, C12, C21; BLUEPRINT §§1–8, 10–15

## Context

The founder's ORAN Audit Report Review conversation states four domains (user, organization, community, admin), extensive relevant profiles and AI-assisted matching, organization-owned resources, admin-approved community verification and scheduled reverification by location, and resource acquisition independent of partners. The explicit continuation authorizes reconciling these requirements and the Windows 11 ARM64 Cursor/PowerShell/pnpm contract in this repository via reviewed PR.

The foundation in PR #1 instead proposed anonymous-only discovery, no stored circumstances, no seeker AI recommendations, deferred organization accounts and a partner-first catalog. Those assumptions conflict with the founder's direction. Preserve the useful provenance, single acceptance path, modular monolith, real-database testing and evidence gates.

## Options considered

1. Keep the narrow directory/partner-first blueprint. Contradicts the founder's requested product.
2. Add an authoritative amendment and reconcile conflicting passages in place. Retains existing work and gives contributors one coherent direction.
3. Replace the foundation or begin implementation immediately. Discards useful work or bypasses unresolved approval gates.

## Decision

Adopt option 2. The founder principles and native environment contract are authoritative; this ADR records explicit direction rather than approving implementation choices.

- All four experiences are foundational in one app: user profiles and grounded assistance; organization ownership; approved scoped community contribution/verification; admin governance.
- Organization and community acquisition must sustain a catalog without an institutional agreement. Future 211/CIE and other authorized integrations complement it.
- Matching combines deterministic published constraints with staged AI interpretation and evidence-grounded explanations. Unknowns are explicit; relevance, verification and availability stay distinct. No fabricated facts or guaranteed qualification.
- Anonymous discovery remains available. Private profiles are voluntary, purpose-specific and protected by consent, access, retention and deletion controls; no default sensitive-profile transmission to external models.
- Native Windows ARM64, Cursor, PowerShell, Node and pnpm form the target local contract in AGENTS.md. WSL, Docker and local containers are optional. Isolated remote development and real-database CI provide alternatives; never use production as development.
- Amend C8/C12 for privacy and authorization, and C21 so explicit founder amendments govern prior assumptions. Keep §15 and CONSTITUTION synchronized.

## Consequences

README, AGENTS, blueprint, Constitution, decisions and ADR-0001 now acknowledge the amendment. Legacy code, historical audit evidence, source licensing controls and unrelated open decisions are preserved.

D0, architecture/schema approval, exact tool pins, provider/model selection, privacy implementation, pilot recruitment, budget, licences, deployment and archive timing are not approved by this record. No app, dependencies, migrations, workflows, resources or production changes are authorized here. Windows compatibility remains a requirement until actual onboarding and checks are recorded.

Review this amendment against the existing foundation branch, then carry that foundation through its existing PR to main after review. The existing PR and reference repository remain intact.
